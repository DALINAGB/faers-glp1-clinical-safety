# faers-glp1-clinical-safety
Pipeline analítico y monitoreo de seguridad clínica para agonistas GLP-1 basado en reportes trimestrales de farmacovigilancia de FDA FAERS.

2. OBJETIVO
En 2-3 lineas: que problema resuelve este proyecto y para quien.
DS/DA: que decision de negocio se apoya con este analisis o modelo
Web: que necesidad del usuario resuelve el sitio o app
QA: que riesgo o bug se busca prevenir con el plan de pruebas
UX-UI: que problema de experiencia o usabilidad se busca resolver

3. PLAN DE TRABAJO (3 a 5 pasos)
1. Exploracion inicial
DS/DA: exploracion de datos | Web: research y wireframe | QA: analisis de requisitos | UX-UI: research de usuario
2. Preparacion
DS/DA: limpieza de datos | Web: arquitectura y stack | QA: diseno de casos de prueba | UX-UI: user flows y wireframes
3. Construccion
DS/DA: modelo o dashboard | Web: desarrollo del sitio/app | QA: ejecucion de pruebas (manuales/automatizadas) | UX-UI: prototipo de alta fidelidad
4. Evaluacion
DS/DA: metricas (AUC-ROC, Recall, etc.) | Web: pruebas de funcionamiento y performance | QA: cobertura de pruebas y bugs encontrados | UX-UI: testeo de usabilidad
5. Conclusiones y proximos pasos
(Ajusta la cantidad de pasos segun la complejidad real, no rellenes por rellenar.)

Resumen breve de las decisiones tecnicas reales.

6. RESULTADOS
DS/DA: metrica principal y resultado final, que modelo funciono mejor
Web: funcionalidades entregadas y como se comporta el producto
QA: bugs encontrados, severidad, cobertura lograda
UX-UI: resultados del testeo de usabilidad, cambios aplicados al diseno
